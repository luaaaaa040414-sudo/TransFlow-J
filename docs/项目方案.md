> 项目代号建议：**TransFlow-J**（Translation Pipeline with Journal Style）
> 版本：v0.2 已确认决策稿　|　日期：2026-10-15

| 决策项 | 结论 |

## 一、项目定位

做一个**可复现、可解释、可视化**的翻译生产系统，把"译前准备 → 翻译 → 校对反思"这条人工流程工程化，并额外增加一个**期刊风格引擎**，让译文不只"准确"，还能"像目标期刊写的"。

三个核心诉求，对应三层设计：

| 诉求 | 设计应答 |
|---|---|
| 翻译必须精准无错 | 术语强约束 + 权威信源核查 + 多模型互校 + 术语回溯校验 |
| 校对要用同等智力水平的不同模型 | 模型异构池（不同厂商/不同架构），避免同源模型同错 |
| 能按指定期刊的风格翻译 | 风格引擎：语料采集 → 风格画像 → 双路径注入（提示词 / 微调） |

---

## 二、总体架构

```
输入（源文本 + 术语库 + 权威信源清单 + 目标期刊）
   │
   ├─▶ ① 译前准备 ── 术语抽取 → 信源核查 → 术语表锁定
   │                                    │
   ├─▶ ② 翻译 ───────── 模型A 生成初译 ◀─┤ 风格约束注入
   │                                    │
   ├─▶ ③ 校对反思 ──── 模型B 独立重译 → 模型C 裁决 → 差异报告
   │
   └─▶ ④ 定稿交付 ─── 风格校准 → 术语回溯 → 反思报告 + 译文

              ▲
        【期刊风格引擎】（横向贯穿，见第五节）
              ▲
        【可视化控制台】（观测全流程，见第六节）
```

**关键设计判断：风格不是最后一步。**
如果等译文定稿再"润色成期刊风格"，会破坏已经校验过的术语和句法。风格约束必须在**生成阶段**（第②步）就以提示词/范例的形式注入，在校对阶段（第③步）作为**评分维度**验收。

## 三、模块一：译前准备

### 3.1 流程

1. **术语候选抽取**
   - 源文本 → 自动抽取候选术语（名词短语、领域高频词、缩写）
   - 方法：spaCy / HanLP 词性与句法分析 + 频次与互信息统计，LLM 辅助筛除通用词
2. **权威信源核查**
   - 每个候选术语 → 检索你提供的**权威信源清单**（术语库、标准、官方译名表、权威机构网站）
   - 命中即锁定为"**强制译法**"（hard constraint）
   - 未命中 → 进入"待定"，由 LLM 生成候选译法 + 标注来源与置信度
3. **术语表锁定**
   - 输出结构化术语表：`源词 | 目标词 | 词性 | 来源 | 置信度 | 是否强制 | 备注`
   - 兼容你已有的 `简洁版本校史馆术语库_终稿v3.1_MemoQ导入.xlsx` 格式，可直接双向导入导出
4. **平行文本收集**（可选）
   - 检索同领域已发表的双语材料，作为风格与搭配参考

### 3.2 输出物

- `glossary.locked.json` — 锁定术语表（供第②③步强制引用）
- `glossary.review.xlsx` — 人工复核表（待定术语需你确认）

### 3.3 精准性的三道锁

| 锁 | 机制 |
|---|---|
| 锁定 | 强制术语在提示词中声明"不得改写、不得变体" |
| 回溯 | 译文中逐个术语反查是否出现且形式一致，缺失即报错 |
| 拦截 | 出现术语变体（大小写、单复数、连字符差异）时自动标红 |

## 四、模块二 & 三：翻译与校对反思

### 4.1 翻译（第②步）

- 输入：源文本 + 锁定术语表 + 风格约束包
- 执行：主译模型（模型 A）分段翻译，**分段而非整篇**，便于定位与增量重译
- 约束注入顺序（优先级从高到低）：
  1. 强制术语
  2. 期刊风格规则（硬性，如"避免第一人称"、"方法用过去时"）
  3. 期刊风格范例（few-shot，3–5 段真实语料）
  4. 通用翻译质量要求（忠实、通顺、无漏译）

### 4.2 校对反思（第③步）

这是你项目里最有学术价值的一环。设计成**三方结构**：

| 角色 | 模型 | 职责 |
|---|---|---|
| 主译 | 模型 A | 出初译稿 |
| 复核 | 模型 B（**不同厂商/不同架构**） | 不看 A 的过程，独立重译一遍 |
| 裁决 | 模型 C（第三种模型） | 对比 A 稿与 B 稿，逐句给出采纳建议 + 理由 |

**为什么必须异构？**
同源模型（如同一厂商不同版本）会共享相同的训练偏差，错的地方一起错、对的地方一起对，互校就失去了意义。所以模型池要跨厂商、跨架构。

**差异报告包含：**
- 逐句对齐的 A 稿 / B 稿 / 裁决稿
- 分歧类型标注：术语、逻辑、语气、省略、增译、风格
- 每处分歧的**理由说明**（这是反思报告的核心，也是你作业里"反思"部分可以直接用的素材）
- 未解决分歧清单（需人工介入）

### 4.3 反思报告自动生成

把第③步的差异数据渲染成结构化报告：
- 分歧统计（按类型、按严重度）
- 典型错例分析
- 术语一致性报告
- 风格契合度评分（来自风格引擎）
- 本次翻译的"经验沉淀"→ 可回写进术语库和风格提示词卡

## 五、模块四：期刊风格引擎（重点）

### 5.1 先澄清一个概念

期刊风格 = **目标期刊的英文写作规范与文风**。汉译英时，是要让译文读起来像该刊的稿件，而不是像"翻译腔的通用英文"。这个定位决定了技术路线。

### 5.2 语料采集

**只采合法开放获取（OA）来源**，这是硬红线：

| 来源 | 内容 | 获取方式 |
|---|---|---|
| DOAJ | 全 OA 期刊元数据与全文链接 | 官方 API |
| arXiv | 预印本全文 | 官方 API，允许批量 |
| PLOS 全系列 | 期刊全文 | 官网开放接口（CC-BY） |
| eLife | 期刊全文 | 官网开放接口 |
| Frontiers | 期刊全文 | 官网开放接口 |
| MDPI 全系列 | 期刊全文 | 官网开放接口 |
| PeerJ | 期刊全文 | 官网开放接口 |
| bioRxiv / medRxiv | 预印本 | 官方 API |

**目标期刊清单（v0.2 确定）**：
- 大类：综合开放获取（ interdisciplinary OA ）
- 具体优先采集：`PLOS ONE`、`Scientific Reports`、`PeerJ`、`MDPI Sustainability`（示例位，最终名单可与用户再校准）

> 上述期刊均为 CC-BY 或等效开放许可，全文可合法采集，且**风格差异明显**（PLOS ONE 长句结构化、Scientific Reports 紧凑、PeerJ 活泼），正是做风格判别实验的理想对照组。

采集要点：
- 遵守 `robots.txt`，请求限速（建议 ≤1 req/s），带真实 UA
- 记录来源 DOI / URL，保证可追溯（学术诚信）
- 按期刊、学科、年份分桶存储

### 5.3 风格画像（Style Profile）

对每个期刊抽取**可量化的风格特征**，这是"可解释"和"可可视化"的基础：

| 层级 | 特征 |
|---|---|
| 词汇层 | 术语密度、名词化比例、缩写使用率、拉丁词源词占比、第一人称频率 |
| 句法层 | 平均句长、句长标准差、从句嵌套深度、被动语态比例 |
| 篇章层 | 衔接词分布（however / therefore / moreover）、新旧信息推进方式、段落长度 |
| 语用层 | 模糊限制语（may / suggest / likely）频率、自称方式（we / this study）、时态惯例 |
| 格式层 | 摘要结构（结构化 vs 非结构化）、数字与单位写法、标题风格 |

输出：`journal_profiles/{journal}.json` + 雷达图数据。

### 5.4 双路径实现

#### 路径 A — 风格提示词卡（推荐先做，1–2 天可落地）

1. 从语料中抽取 3–5 段最能代表该刊风格的范例
2. 把风格画像翻译成**可执行的写作规则**（如"平均句长 22–28 词，被动语态 ≤15%，方法段用过去时"）
3. 组装成"风格提示词卡"，注入第②③步
4. 用 **RAG 检索**：按当前段落主题，从语料库中检索最相似的范例段落作为 few-shot

**优点**：无需训练，立刻可用，规则可读可改，便于写进论文方法部分。

#### 路径 B — 训练小模型（v0.2 已确认：B1 与 A 并行推进）

这里拆成**两个不同性质的小模型**，难度和收益完全不同：

**B1. 期刊风格判别器（Style Classifier）— 已确认，本轮必做**
- 任务：输入一段英文，输出它属于哪个期刊（或"符合某刊风格"的概率）
- 数据：直接用采集到的期刊语料，**无需平行语料**，天然可训练
- 模型：TF-IDF + 逻辑回归（基线，CPU 秒级）→ 微调 MiniLM / DistilBERT（提升上限）
- 用途：
  - 给译文打**风格契合度分数** → 直接喂给可视化雷达图
  - 作为校对阶段的"第四个审稿人"
  - 量化验证路径 A 的提示词是否真的有效（**对比实验数据，论文直接可用**）
- 数据量：每刊 300–500 段即可得到可观效果

**B2. LoRA 风格改写模型 — 暂缓，作为可选扩展**
- 任务：把"通用译文"改写成"期刊风格译文"
- **核心难点**：期刊语料是英-英单语，没有"通用版 → 期刊版"的平行对，缺少监督信号
- 可行方案（伪平行数据构造）：
  1. 用强模型把期刊原文**反向改写成"通用学术英文"**（降级版）
  2. 得到伪平行对：（通用版, 期刊版）
  3. 用 LoRA 微调 Qwen3.5 系列的小尺寸模型（27B 及以下，4bit 量化）学习"升级"映射
  4. 用 B1 判别器做**奖励信号**，做 DPO 偏好优化
- 硬件：3B 模型 LoRA 在 8–16GB 显存可跑
- **风险**：伪平行数据的质量上限决定了模型上限；可能不如路径 A 稳定
- **当前决策**：先不做。等 A + B1 跑通、风格画像和判别器就绪后，伪平行数据的构造才有意义（B1 判别器正是 B2 的质量守门员）。

### 5.5 风格契合度评分

无论走哪条路径，最终都产出一个统一指标：

```
风格契合度 = w1 × 特征距离(译文画像, 期刊画像)
           + w2 × 判别器置信度
           + w3 × 术语一致性
```

这是可视化里最直观的一个数字。

## 六、可视化控制台

### 6.1 界面分区

| 区域 | 内容 |
|---|---|
| 顶部工具栏 | 选择目标期刊、源语言/目标语言、模型池配置 |
| 左栏 · 工作台 | 源文本输入 / 文件上传、术语库加载、权威信源清单 |
| 中栏 · 流水线视图 | 四阶段实时进度条，每阶段可展开查看中间产物 |
| 中栏 · 双栏对照 | 原文 / 译文 / 修订稿三列对齐，差异高亮，分歧处可点击看理由 |
| 右栏 · 术语面板 | 命中术语、待定术语、术语回溯校验结果（红色告警） |
| 底部 · 风格雷达图 | 译文画像 vs 目标期刊画像，五维叠加对比 |
| 底部 · 反思报告 | 分歧统计、典型错例、一键导出 Word/PDF |

### 6.2 可视化要点

- **流水线状态机**：四阶段节点实时点亮，失败可重试单阶段（不重跑全程）
- **术语命中热力图**：源文本中标出已锁定 / 待定 / 缺失术语
- **模型分歧条形图**：按分歧类型统计，直观看到哪个环节最容易出问题
- **风格雷达图**：词汇/句法/篇章/语用/格式 五维，译文与目标期刊叠加
- **版本时间轴**：初译 → 复核 → 裁决 → 定稿，可回溯每一步

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 抓取期刊全文的版权风险 | 只采 OA 来源与公开摘要，记录 DOI 可追溯 |
| 被目标站点封禁 | 遵守 robots.txt，限速 ≤1 req/s，优先官方 API |
| 小模型训练效果不及预期 | 先用 B1 判别器拿到确定收益；B2 定位为探索实验，负结果也是材料 |
| 术语准确性与 LLM 幻觉冲突 | 权威信源优先级最高，LLM 只做候选不做裁定 |
| 互校模型同源导致同错 | 强制跨厂商、跨架构选型 |
| 长文本上下文超限 | 分段翻译 + 术语表全程注入 + 段落间衔接校验 |
